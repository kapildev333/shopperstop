## Findings
1. MEDIUM, `apps/admin/src/order-board.tsx:41-48` (the `heard` baseline). Fold into task 2 or fix before it (small, own test). A remount with a cached answer announces orders that arrived while the board was away. Scenario: admin on store A sees SS-1; selects B (board keyed by store, remounts); core gets SS-2 for A; admin selects A again (or leaves /orders and returns inside gcTime, 5 min). `useQuery` returns A's cached answer at once, `heard` is empty, so the stale answer becomes the silent baseline; the refetch on mount then returns SS-1 and SS-2, and "New order SS-2" is read out although the page was just opened. Spec: nothing on a store change or on stale data. Not tested (the store-change test only covers a store never visited). Smallest fix: take a baseline only from an answer fetched since mount, i.e. condition the block on `board.isFetchedAfterMount` (`if (board.data && board.isFetchedAfterMount && heard?.from !== board.data)`), plus a test that goes A, B, A with an order added to A in between and expects an empty region. The cached cards still show immediately.
2. LOW, `order-board.tsx:59`. `placedAt.localeCompare` sorts RFC 3339 strings lexically. Core serves UTC `time.Time` (RFC3339Nano, trailing zeros trimmed), so "…:00.5Z" sorts before "…:00.50001Z" wrongly and locale rules apply. Order within one second only. Fix: `Date.parse(a.placedAt) - Date.parse(b.placedAt)`. Fold into task 2 (it touches the same file).
3. LOW (ceiling), `orders.ts:34-38`. Each column holds the 100 newest of its status (core: `order by placed_at desc, id desc`, pageSize max 100, the client ignores `total`). With more than 100 waiting, the oldest, the ones that most need attention, are the ones dropped, and the heading count says 100. The `ponytail:` comment says "newest 100" and the request to core for an active filter with a total is logged. Accept as ceiling; if cheap in task 6, show "100+" when a status returns `items.length === 100`.
4. LOW (ceiling), `orders.ts:34`. Five parallel reads are not one snapshot: an order moved between two reads can show in two columns or in none for one poll (keys are per column, so React does not complain). Whole-board semantics are right otherwise: `Promise.all` makes one failing request fail the board; on first load that is the retry alert, on a later poll TanStack keeps the old data and the root `RefetchNotice` says so, so no stale column sits next to fresh ones. Task 3's `cancelQueries` + `setQueryData` after a status change must write the whole five-status array, which it already does by design. Accept.
5. NIT, `orders.ts:46-50`. The leaf ticks every 5 s per card (one `setInterval` per card; the brief and spec say once a minute). Correct, since the snapshot is a string and React re-renders only on change, but 100+ cards means 100+ timers. A module-level shared subscriber set with one interval would do. Accept; revisit only if the board grows.
6. NIT, test gaps, none blocking. No test for: one of five requests failing (first load or poll); the poll stopping on unmount or sign-out; no overlapping polls with a slow core (TanStack dedupes an interval fetch while one is in flight, I checked the library path); a 401 on a poll (handled by the existing `onUnauthorized` clear, and sign-out `queryClient.clear()` runs only until `navigate` unmounts the board). The hidden-tab test relies on `refetchOnWindowFocus` plus the default `staleTime: 0` in `router.ts`; a `staleTime` added there would break "ask at once" and the test would catch it. Add the one-of-five test in task 2 or 3 if convenient.
7. NIT, `order-board.tsx:66`. Heading text is "Placed" plus a `Badge` count with no space; the unit test asserts `Placed2` from `textContent`. The region name regexes `^Placed` are fine. Check in the first browser run how the accessible name reads (flex children normally get a space); if not, add `aria-label` or a visually hidden space. Accept.
8. NIT, hours wording: 30 h reads "30 h 0 min ago" (no "yesterday"); this is what the spec says. Accept. An unparsable `placedAt` would read "NaN h NaN min ago"; core always sends valid UTC. Accept.

## Checked and correct
- Contract: `GET /admin/stores/{id}/orders?status=&pageSize=100`, one status per request, five per poll, field names (`number`, `placedAt`, `items[].quantity`, `totalCents`, `address.pincode`) match `core.d.ts` and the handler; `pageSize` 1 to 100 is core's limit; other store's staff and an unknown store are 404 (handler line 175) and store staff never call the list of stores (test asserts the exact paths).
- Polling: `refetchInterval: 10_000`, background polling off by default, focus/visibility refetch on show; the board is keyed `['admin','orders',storeId,'board']` and the route keys `OrderBoard` by store, so a poll on another store cannot write into the showing board and all per-store state (`heard`) is dropped on a change.
- Announcements: only `placed` orders absent from the previous answer of the same mounted board; none on the first answer, on an identical answer (structural sharing keeps the same object, so the region is not rewritten, and a MutationObserver test proves it), or on a failed poll (no new data). Singular and plural wording right. `sr-only` (clipped, not `display:none`), `role="status"` (polite), present in both the board and empty branches from the first render of data. No order can return to `placed`: `status.go` has no move into it, so "leaves and returns" cannot happen.
- Time since: `useSyncExternalStore` leaf with a stable module-level subscribe, string snapshot (re-renders only on text change), SPA only so no server snapshot needed; boundaries 0/59 s just now, 60 s 1 min, 3599 s 59 min, 3600 s 1 h 0 min tested, future time clamps to just now. Fake timers are per test with `useRealTimers` in `afterEach`; Testing Library waits work via `shouldAdvanceTime`; no flake in four full runs.
- Store selection mirrors admin-stock (`store` search validated to string, unknown falls back to the first store, `storeNameQuery`, no `GET /admin/stores` for staff). Layout: five columns from `lg`, stacked below (no horizontal scroll, so nothing to reach by keyboard); sections are labelled regions, cards are list items; empty column says "No orders"; only `@shopperstop/ui` components and semantic classes, no literal colours. The sr-only live line is page markup (already requested of ui in the lane log).
