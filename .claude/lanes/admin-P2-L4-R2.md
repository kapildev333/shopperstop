## Findings, most severe first
1. medium, fix before task 3 (`apps/admin/src/routes/_staff/stock.tsx:76` `edit()` calls `save.reset()`): an edit typed while the save is in flight detaches the observer from the running mutation (checked in `node_modules/@tanstack/query-core/src/mutationObserver.ts:188`: `reset()` removes the observer and clears the current mutation). Consequences: `save.isPending` turns false, so the Save button stops showing `loading` and is clickable again; a second click sends a second PUT with the first save's rows again (same values, so set semantics make it harmless to core, but it is "sent twice"); when the first save finishes, `save.isSuccess` is false, so "Stock saved." is never shown for rows that were saved. Data is not lost (the mutation's own `onSuccess` still runs and keeps the new edit), which is why the in-flight test passes. Smallest fix: in `edit()` and `discard()` call `save.reset()` only when `!save.isPending`; a failure alert (task 3) is cleared the same way. Add one test line: type during the save, press Save again, `puts` still has length 1.
2. medium, fix before task 3 (`stock.tsx:196`, `Button loading`; `packages/ui/src/button.tsx:39` sets `disabled={disabled || loading}`): pressing Save makes the focused button `disabled`, so keyboard focus falls to `body` for the duration of the save, the exact thing the file's `idle` comment says to avoid. Screen-reader and keyboard users lose their place on every save. Smallest fix: do not pass `loading`; use `aria-disabled={count === 0 || save.isPending}` and the label "Saving..." (or `aria-busy`), with the click guard that already exists (`save.isPending` returns early). The text change is announced by the `StatusMessage` below.
3. low, fix before task 3, one line (`stock.tsx:185`): the "No unsaved changes / n unsaved changes" `<p>` is not a live region, and the brief asked that the count be announced. "Stock saved." is (`StatusMessage` is `role="status"`), the count is not. Fix: `role="status"` on the `<p>` (it renders from the first paint, which is fine for a polite region). Do not move focus.
4. low, fold into task 3 (`stock.tsx:56-63`, `draft.store`): the draft keeps store A's edits after a switch to B until B is edited (they are hidden, not dropped). Switching A to B to A through the URL (or the selector, task 2 has no dialog) shows A's edits again, while the spec's task-3 scenario says that after "Discard and switch" and a return the field holds what core holds. Task 3's "Discard and switch" must call `setDraft({store: chosen, edits: {}})`, and a store changed by URL/Back/Forward should drop the draft too, or the spec line "Edits SHALL never be shown for... a store other than the one they were typed for" is only half true (they are shown again on return). Never sent to the wrong store: confirmed, `submitSave` sends `edits` of the displayed store and the mutation carries `sent.store`.
5. low, fold into task 3 (`stock.tsx:83`): `value.trim() === String(row.quantity)` makes `07` on a row holding 7 an edit (badge, count, a row sent that changes nothing). Compare `parseQuantity(value) === row.quantity` instead; same result for every other input. Also `discard` is unguarded for `count === 0` (`onClick={discard}`): its `aria-disabled` is only visual, and pressing it clears the "Stock saved." message. Guard `count > 0 &&` like Save does.
6. low, accept as ceiling (`stock.tsx:82-84`): an edit typed during a save back to a saved row's old quantity is dropped as "typed back" (the displayed row still holds the old value), so the user's revert is lost; the field then shows the new value after the refetch.
