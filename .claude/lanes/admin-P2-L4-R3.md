## Findings, most severe first
1. HIGH, fix before the PR (`apps/admin/src/routes/_staff/stock.tsx:42-43`, `mutationFn`: `if (error) throw error.error`). openapi-fetch returns `error: undefined` for a non-ok answer with `Content-Length: 0` and `error: ""` for an empty body; both are falsy. Checked against `node_modules/openapi-fetch/dist/index.mjs:178-201` and by running it: a `502` with no body gives `{error: ""}` and "treated as success". That is what Caddy (prod-local) and the Vite proxy (dev) answer when core is down or restarting. Failing scenario: an admin types a quantity, core is down, presses Save: `mutationFn` resolves, `onSuccess` clears the edit, "Stock saved." is shown, nothing was saved. A non-JSON non-empty body (`Bad Gateway` text) is the second hole: `error.error` is `undefined`, `throw undefined` leaves `save.error` falsy, so `saveError` is `undefined` and the page shows nothing at all (edits kept, no alert). The tests pass because the fake core always answers JSON error bodies. Smallest fix: take `response` too, `if (!response.ok) throw error?.error ?? {}` (then `saveError.code` is `undefined` and the generic alert shows), plus one test: `PUT` answers `new Response(null, {status: 502})`, expect the "Could not save the stock. Try again." alert, the edit kept and no "Stock saved.". Same pattern exists app-wide (`if (error) throw error.error` in 17 places) but only this page shows a success message from it; the rest can stay.
2. MEDIUM, fix before the PR (`apps/admin/src/routes/_staff/stock.tsx:280`, `validateSearch`: `.slice(0, maxSearch)`). `slice` counts UTF-16 units and can cut an emoji in half. Failing input: `/stock?q=` + 99 `a` + `😀` + `b` gives a 100-unit `q` ending in a lone surrogate; the request builder (`encodeURIComponent`) throws `URI malformed` (run in node), so the stock query errors with "Could not load the stock." and Try again cannot fix it, which the spec line "No value of the URL SHALL leave the page on a failed load that Try again cannot fix" forbids. Core counts runes (`utf8.RuneCountInString`) so a rune cut is safe. Smallest fix: `Array.from(text).slice(0, maxSearch).join('')` (or `.toWellFormed()` after the slice), plus a case in the NUL/100 test with the emoji at position 100.
3. LOW, fix before the PR or accept (`stock.tsx:62-63`, `saved` / `saveError`; `save.reset()` is only called by an edit or Discard). The result of the last save is tied to the store, not cleared by a store change. Scenario: save at A fails (or core answers 400 `validation`), the admin presses "Discard and switch" to B, then goes back to A: A shows "These changes were refused: ... Discard the changes and try again." with "No unsaved changes" and nothing to discard. The same for "Stock saved." reappearing on return. Smallest fix: show `saveError` only while `count > 0` (and optionally `save.isSuccess` only when no store change since); or call `save.reset()` in the "Discard and switch" handler when not pending.
4. LOW, accept as ceiling or one-line fix (`stock.tsx:229`, dialog text). Dialog open (edits exist, save running), the save finishes and clears the edits: the text reads "discards the 0 unsaved changes". Rare. Fix: `count === 0` guard or close the dialog when `count` drops to 0.
