## Found
No blockers. Nits, all "can ride with the nits task after task 5":
- Nit (low, a11y), apps/admin/src/image.tsx:68 `disabled={upload.isPending}`: disabling the focused input drops keyboard focus to body mid-upload, and a keyboard user must tab back in. Fix: drop `disabled` (the mutation is idempotent; a second pick during pending can be ignored with `if (upload.isPending) return` in `pick`) or use `aria-disabled`.
- Nit (low), image.tsx:12-13 vs core: client refuses by `file.type`; core judges by content. A valid PNG with an empty or wrong `file.type` (some OS/browser combos for .webp, or a renamed file) is refused client-side although core would accept it. Safe direction (never sends something core accepts less), so acceptable; note only.
- Nit (low), `products/$productId.tsx` line 26: `ImageUpload` has no `key`; `url`/`version` are initial-state only. If the page ever changes `productId` without unmounting (route param change in place), the tile shows the previous product's image. `ProductForm` already has `key={product.data.id}`. Fix: add `key={product.data.id}` to `ImageUpload`.
- Nit (low), same cause: `url` ignores later `imageUrl` props (a background refetch after another admin's upload). Acceptable for a single-admin tool; the next full load shows it.
- Nit (low), categories.tsx dialog: the `ImageUpload` sits inside the `<form>`; its file input has no `name`, so it is not submitted, and Enter in the file input does nothing harmful. Fine, but a pending upload does not block Save/Cancel; closing the dialog mid-upload still lets the PUT finish and invalidate. Acceptable.
- Nit (test gap), image.test.tsx: add `expect(screen.queryByRole('alert')).not.toBeInTheDocument()` to the refusal test, and one test that `/categories` "New category" dialog has no Image field.
- Nit (a11y, visual): hint text "Saved as soon as you pick it." is clear; the success `StatusMessage` is `role="status"` so it is announced; error is tied through FormField `aria-describedby` and `aria-invalid`. Nothing to fix.
