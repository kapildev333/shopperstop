# Design

## Context
`apps/web` on 5101344 is the Phase 1 shell: `src/routes/__root.tsx` (brand banner with the "Enter pincode" button, `main`, not-found), `src/routes/index.tsx`, `src/shell.test.tsx`, `e2e/smoke.spec.ts`, Playwright starting core on :18080 and `vite preview` on 15173. No API client, no TanStack Query. `@shopperstop/ui/api` exports the generated `paths` and `components` types; on 5101344 they hold only `/healthz` and `/readyz`. Core-P2-L1 (`core-accounts-auth`) adds `/auth/*`, `/me` and `/me/addresses` and the demo customer `demo@shopperstop.local` / `demo12345` seeded by `core-admin seed-demo --reset` (D22). Workers start only once that is on main and `packages/ui/src/api/core.d.ts` carries those paths. Where this design and the generated types disagree on a field name or shape, follow the generated types and say so in the lane log.

## Goals / Non-Goals
**Goals:** the spec delta's five requirements; three worker tasks in sequence; a client and session other web lanes reuse.

**Non-Goals:** guest cart merge (web-P2-L3 adds a call in `startSession`), checkout (web-P2-L4 reuses `AddressDialog` and `useAddresses`), password reset, cross-tab sync, a Checkbox, delete confirmation.

### Session store (`src/session.ts`)
```ts
import { useSyncExternalStore } from 'react'

const key = 'shopperstop:customer-token'
let token: string | undefined = localStorage.getItem(key) ?? undefined
const listeners = new Set<() => void>()

export function getToken() {
  return token
}

export function setToken(next: string | undefined) {
  token = next
  if (next) localStorage.setItem(key, next)
  else localStorage.removeItem(key)
  listeners.forEach((listener) => listener())
}

function subscribe(listener: () => void) {
  listeners.add(listener)
  return () => {
    listeners.delete(listener)
  }
}

export function useToken() {
  return useSyncExternalStore(subscribe, getToken)
}
```
Simplification: no `storage` event listener, so signing out in one tab leaves another tab holding the token until its next 401. Ceiling: add a `window.addEventListener('storage', ...)` when a customer reports it.

### Client (`src/api.ts`)
```ts
import { QueryClient, useQuery } from '@tanstack/react-query'
import createClient, { type Middleware } from 'openapi-fetch'
import type { components, paths } from '@shopperstop/ui/api'
import { getToken, setToken, useToken } from './session'

export type ApiError = components['schemas']['Error']['error']

export const authMiddleware: Middleware = {
  onRequest({ request }) {
    const token = getToken()
    if (token) request.headers.set('Authorization', `Bearer ${token}`)
    return request
  },
  onResponse({ response }) {
    if (response.status === 401) setToken(undefined)
    return response
  },
}

export const api = createClient<paths>({ baseUrl: '/api/core/v1' })
api.use(authMiddleware)

export const queryClient = new QueryClient({ defaultOptions: { queries: { retry: false } } })

const unreachable: ApiError = { code: 'internal', message: 'Could not reach ShopperStop. Try again.' }

// Runs one request; resolves to the envelope's error, or undefined on success.
export async function call(request: () => Promise<{ error?: { error: ApiError } }>): Promise<ApiError | undefined> {
  try {
    const { error } = await request()
    return error?.error
  } catch {
    return unreachable
  }
}

export function splitError(error: ApiError | undefined, fields: readonly string[]) {
  if (!error) return { fields: {} as Record<string, string> }
  if (error.field && fields.includes(error.field)) return { fields: { [error.field]: error.message } }
  return { fields: {} as Record<string, string>, banner: error.message }
}

export function useMe() {
  const token = useToken()
  return useQuery({
    queryKey: ['me', token],
    enabled: !!token,
    queryFn: async () => {
      const { data, error } = await api.GET('/me')
      if (error) throw error
      return data
    },
  })
}
```
- The query key includes the token, so a new session never shows the previous customer's cached data.
- The 401 rule also fires on a failed sign-in; there is no token then, so it is a no-op.
- `call`'s parameter type may need adjusting to what openapi-fetch returns for a route whose error responses are untyped; keep the behaviour (envelope error or `unreachable` on a thrown fetch).
- `retry: false`: a failed query shows its `ErrorBanner` with "Try again" (`refetch`) at once.

`src/routes/__root.tsx` (task 1): `RootLayout` returns `<QueryClientProvider client={queryClient}>...existing banner and main...</QueryClientProvider>`. Keeping the provider in the root route means `shell.test.tsx`'s `renderAt` needs no change.

`src/test-setup.ts` (task 1) adds:
```ts
afterEach(() => {
  setToken(undefined)
  queryClient.clear()
})
```

### Auth (`src/auth.ts`)
```ts
export function safeReturnTo(raw: unknown): string {
  return typeof raw === 'string' && raw.startsWith('/') && !raw.startsWith('//') && !raw.startsWith('/\\') ? raw : '/'
}

type Session = { token: string; customer: Me }   // Me = the GET /me 200 schema from the generated types

function startSession({ token, customer }: Session) {
  queryClient.clear()
  setToken(token)
  queryClient.setQueryData(['me', token], customer)
}

export async function signIn(body: { email: string; password: string }): Promise<ApiError | undefined>
// POST /auth/sign-in through `call`-style try/catch; on data, startSession(data).

export async function register(body: { email: string; password: string; name: string }): Promise<ApiError | undefined>
// POST /auth/register; on error return it; if the 2xx body has `token`, startSession(it);
// otherwise return signIn({ email, password }).

// task 3
export async function signOut() {
  await call(() => api.POST('/auth/sign-out'))   // result ignored: the session ends locally either way
  setToken(undefined)
  queryClient.clear()
}
```

### Forms (`src/auth-forms.tsx`, task 2)
Forms own no data fetching; each takes `submit: (values) => Promise<ApiError | undefined>` and calls it only after its own checks pass. That keeps the Vitest tests free of HTTP fakes; the real requests are covered by Playwright.

```tsx
export function SignInForm({ submit }: { submit: (v: { email: string; password: string }) => Promise<ApiError | undefined> })
export function RegisterForm({ submit }: { submit: (v: { name: string; email: string; password: string }) => Promise<ApiError | undefined> })
```
- Uncontrolled inputs read with `new FormData(event.currentTarget)`; `<form noValidate>` so the messages are ours, not the browser's.
- Each field: `<FormField label=... error={errors.fields.<name>}><Input name=... type=... autoComplete=... /></FormField>`. Labels "Name", "Email", "Password". `autoComplete`: `name`, `email`, `current-password` (sign-in), `new-password` (register). Register shows the hint "8 to 72 characters" on the password.
- Client messages: "Enter your name", "Enter your email", "Enter your password", "Use 8 to 72 characters" (`new TextEncoder().encode(password).length` outside 8..72; register only).
- Server result goes through `splitError(error, ['email', 'password'])` (register adds `'name'`); `banner` renders `<ErrorBanner message=... />` above the button.
- Submit button `<Button type="submit" size="lg" loading={pending} className="w-full">`: "Sign in" / "Create account".
- State: one `useState` for `{ fields, banner? }`, one for `pending`.

### Pages (task 2)
`src/routes/sign-in.tsx`:
```tsx
export const Route = createFileRoute('/sign-in')({
  validateSearch: (search: Record<string, unknown>): { returnTo?: string } =>
    typeof search.returnTo === 'string' ? { returnTo: search.returnTo } : {},

```
`SignIn` renders `PageHeader title="Sign in"` and a `Card className="mx-auto w-full max-w-md p-6"` holding `SignInForm` and, below it, `New to ShopperStop? <Link to="/register" search={{ returnTo }}>Create an account</Link>` (link classes `text-accent underline`; the text is `ink` on `surface`). `submit` = `async (v) => { const error = await signIn(v); if (!error) navigate({ href: safeReturnTo(returnTo), replace: true }); return error }`. If `navigate({ href })` does not type-check in router 1.170, use `router.history.replace(safeReturnTo(returnTo))` from `useRouter()`.
`src/routes/register.tsx`: same shape, title "Create your account", `RegisterForm`, link "Already have an account? Sign in" to `/sign-in` with the same `returnTo`.
The page title is the only `h1`; everything sits on `surface` cards (ink-muted on canvas is 4.47:1).

### Header (`src/account-link.tsx`, task 3)
```tsx
const RouterButtonLink = createLink(ButtonLink)

export function AccountLink() {
  const token = useToken()
  const me = useMe()
  const location = useLocation()
  if (!token) {
    const onAuthPage = location.pathname === '/sign-in' || location.pathname === '/register'
    const returnTo = onAuthPage ? (location.search as { returnTo?: string }).returnTo : location.href
    return <RouterButtonLink variant="secondary" to="/sign-in" search={returnTo ? { returnTo } : {}}>Sign in</RouterButtonLink>
  }
  return (
    <RouterButtonLink variant="secondary" to="/account">
      <UserRound size={16} aria-hidden />
      {me.data?.name ?? 'Account'}
    </RouterButtonLink>
  )
}
```
`secondary` is the only button style that passes contrast on the brand band (web-P1-L1 finding). In `__root.tsx` the banner's right side becomes `<div className="flex items-center gap-2">{pincode Button}<AccountLink /></div>`; nothing else in the header changes.

### Account page (`src/routes/account.tsx`, task 3)
- `createFileRoute('/account')({ component: Account })`. `Account`: `const token = useToken(); if (!token) return <Navigate to="/sign-in" search={{ returnTo: '/account' }} replace />`, else `<AccountPage />`. One guard covers first load and a token dropped by a 401 mid-visit. No `beforeLoad`.
- `export function useAddresses()`: `useQuery({ queryKey: ['addresses', token], enabled: !!token, queryFn: GET /me/addresses })`, returning the list (`data.items` if the contract wraps it in the list envelope, else the array; follow the types). Exported for web-P2-L4.
- Layout: `PageHeader title="Your account" actions={<Button variant="secondary" onClick={onSignOut}>Sign out</Button>}`, then `<div className="grid gap-6 lg:grid-cols-2">` with two `Card className="p-6"`, each starting with an `h2` (`text-h2 text-ink`): "Profile" and "Addresses".
- Profile: while `useMe` loads, two `Skeleton`s; on error `ErrorBanner` with `onRetry={refetch}`. Form (uncontrolled, `defaultValue` from `me.data`, `key={me.data.id}` or equivalent) with "Name" (required: "Enter your name") and "Phone" (`type="tel"`, `autoComplete="tel"`), "Save" button; `PATCH /me` with `{ name, phone }` (empty phone sent as `""`, see proposal request 2); errors via `splitError(error, ['name', 'phone'])`; on success `queryClient.setQueryData(['me', token], data)` or invalidate `['me']`, and `<StatusMessage tone="success">Saved</StatusMessage>` until the next edit or submit.
- Addresses: loading `Skeleton`s; error `ErrorBanner` with retry; empty `EmptyState title="No addresses yet" description="Add one to check out faster." action={<Button onClick={openAdd}>Add address</Button>}`; otherwise a `ul` of rows (`border-t border-line` between them): label in `text-h3`, `<Badge variant="success">Default</Badge>` on the default, `line1`, `line2` when present, `pincode` in `text-body text-ink-muted`; actions `Button variant="ghost"`: "Edit", "Set as default" (hidden on the default), and `variant="ghost-danger"` "Delete"; each action button gets `aria-label` naming the address (`Edit Home`, `Set Home as default`, `Delete Home`) so repeated buttons are distinguishable. Below the list, `Button variant="secondary"` "Add address". Row action failures show one `ErrorBanner` at the top of the card.
- Mutations are plain `async` handlers through `call(...)`, then `queryClient.invalidateQueries({ queryKey: ['addresses'] })`; no `useMutation`. Set as default = `PATCH /me/addresses/{id}` `{ isDefault: true }`. Delete = `DELETE /me/addresses/{id}`, no confirm.
- Sign out: `await signOut(); navigate({ to: '/' })`.

### Address dialog (`src/address-dialog.tsx`, task 3)
```tsx
export type AddressValues = { label: string; line1: string; line2: string; pincode: string }

export function AddressDialog(props: {
  open: boolean
  address?: AddressValues          // present = edit
  onClose: () => void
  submit: (values: AddressValues) => Promise<ApiError | undefined>
})
```
- `Dialog title={address ? 'Edit address' : 'Add address'}`; a `form noValidate` inside with `FormField`s "Label" (hint "Home, Work"; required: "Enter a label"), "Address line 1" ("Enter the first address line"), "Address line 2" (hint "Optional"), "Pincode" (`inputMode="numeric"`, `autoComplete="postal-code"`, `/^\d{6}$/` else "Enter a 6-digit pincode"); `DialogFooter onCancel={onClose}` with `<Button type="submit" loading={pending}>Save address</Button>`. Errors via `splitError(error, ['label', 'line1', 'line2', 'pincode'])`; on success `onClose()`.
- The account page wires `submit`: add = `POST /me/addresses` with `line2` omitted when empty; edit = `PATCH /me/addresses/{id}` with all four fields (empty `line2` as `""`); then invalidate `['addresses']`.
- `Dialog` renders `null` when closed, so the form remounts with fresh `defaultValue`s each time it opens.

### e2e
`e2e/global-setup.ts` (task 2), `globalSetup: './e2e/global-setup.ts'` in `playwright.config.ts`:
```ts
import { execFileSync } from 'node:child_process'
import { fileURLToPath } from 'node:url'

export default function globalSetup() {
  const cwd = fileURLToPath(new URL('../../../services/core', import.meta.url))
  execFileSync('go', ['run', './cmd/core-admin', 'migrate'], { cwd, stdio: 'inherit' })
  execFileSync('go', ['run', './cmd/core-admin', 'seed-demo', '--reset'], { cwd, stdio: 'inherit' })
}
```
`make e2e` already runs the same two commands once before all suites; the global setup repeats them so the web suite starts from a fresh demo seed after admin's suite, and so `npm run e2e` works alone. It inherits the `make e2e` environment (database `shopperstop_core_e2e`); use core's actual subcommand and flag names if they differ. Every e2e test that signs in uses either the demo customer (once per run, "Demo customer signs in") or a fresh `e2e-<Date.now()>-<n>@example.com` registered in the test, so reruns do not collide; the customer name is "E2E Shopper". Axe runs as in `smoke.spec.ts` (`new AxeBuilder({ page }).analyze()`, `violations` equal `[]`) on every page and open dialog visited.

### Simplifications and ceilings
- Forms are uncontrolled and validated on submit only. Ceiling: per-field live validation if a form grows past five fields.
- No `useMutation`; handlers call the client and invalidate. Ceiling: optimistic updates if address actions feel slow.
- No delete confirmation. Ceiling: a `Dialog` confirm if deleting an address ever loses order data (it cannot; orders snapshot the address).
- No default checkbox in the dialog (`packages/ui` has no Checkbox); "Set as default" on the list. Ceiling: add it when ui ships a `Checkbox` or checkout needs default-on-create.
- No cross-tab sync (see Session store).
- Header shows the name only after `GET /me`; "Account" while loading. Ceiling: none needed.
- Vitest covers forms and the dialog through a `submit` prop, not HTTP; HTTP behaviour is covered only by Playwright against a real core. Ceiling: by design (no HTTP mocks).

## Risks / Trade-offs
- [Contract differs from Spec 2 §6, e.g. register returns no token, addresses not wrapped in `items`] → workers follow the generated types; `register` handles both token shapes.
- [web-P2-L1 runs in parallel and edits `__root.tsx`, `main.tsx` or adds its own client] → this change owns `src/api.ts` and `src/session.ts`; L1 imports them. Whichever lands second rebases; the header edit here is one line plus the wrapper.
- [Rate limits on a reused core: 10 per email and 100 per IP per hour] → CI starts a fresh core; locally, fresh emails per test and one demo sign-in per run keep about 16 runs an hour under the IP limit. Restart core if `rate_limited` shows.
- [`seed-demo --reset` also resets data admin's suite created] → `make e2e` runs suites one at a time; each starts from its own reset.
- [Phone and line2 clearing semantics] → proposal request 2 to core.
