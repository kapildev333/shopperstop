## Context
`apps/mobile` (mobile-P4-L1, D37) styles with React Native `StyleSheet` and imports token values from `@shopperstop/ui/tokens`; it never copies hex values. Today the values exist only in `packages/ui/src/tokens.css` as CSS custom properties, and `formatInr` lives in `src/price.tsx` next to a React component and the `cn` helper. Metro and Jest in the mobile app resolve package `exports`, so each new entry points at `dist/` like `.` does; `make test-web` builds `packages/ui` before any app gate.

## Goals / Non-Goals
Goals: one generated TS module with the token values a native app needs, a drift test, and a DOM-free `formatInr` entry. Non-goals: changing `tokens.css`, `check-figma-tokens.mjs`, the Makefile, or any app.

## Decisions

### 1. Generator: `packages/ui/scripts/gen-tokens.mjs`
Plain Node ESM, no dependency. Exports `generateTokens(css: string): string` (pure) and writes `src/tokens.ts` only when run directly (`import.meta.url === pathToFileURL(process.argv[1]).href`). Parsing reuses `check-figma-tokens.mjs`'s approach (regex over `--name: value;` pairs inside a block); that script is not imported or changed because it runs at import time.

- `:root { ... }` gives `colors`: every property, name camelCased (`brand-strong` to `brandStrong`), value verbatim (`#E5B51F`), in file order.
- The plain `@theme { ... }` block (regex `/@theme\s*\{([^}]*)\}/`, which skips `@theme inline {`) gives the rest. A missing property throws `tokens.css has no --<name>` so a renamed token fails the gate instead of emitting `NaN`.
  - `radius.control` and `radius.card` from `--radius-control`, `--radius-card` (`parseFloat`, px dropped).
  - `type.<name>` for `display h1 h2 h3 body small button` from `--text-<name>`, `--text-<name>--line-height`, `--text-<name>--font-weight`; `weight` is a number (700). The mobile app maps weight to its `@expo-google-fonts/inter` face.
  - `motion.duration` from `--default-transition-duration` (150), `motion.easing` from `--default-transition-timing-function` (`'ease-out'`).
  - `shadows.card` and `shadows.sheet` from `--shadow-card`, `--shadow-sheet`, parsed by `/^(-?[\d.]+)(?:px)?\s+(-?[\d.]+)(?:px)?\s+([\d.]+)(?:px)?\s+rgba\((\d+),\s*(\d+),\s*(\d+),\s*([\d.]+)\)$/` into `{ boxShadow: <css value verbatim>, offsetX, offsetY, blur, color: '#RRGGBB' upper-case, opacity }`; any other shape throws `unparsed shadow: <value>`. `boxShadow` serves React Native's `boxShadow` style (new architecture); the parts serve iOS `shadowOffset`/`shadowRadius`/`shadowColor`/`shadowOpacity` and an Android `elevation` the app picks.
- Fixed values Spec 1 §8.3 and §8.5 state but `tokens.css` does not declare (they are Tailwind defaults or utilities on the web side) sit in one `FIXED` constant in the script with a comment naming the spec line: `radius.pill` 9999 (`rounded-full`), `spacing` `{ unit: 4, gutter: 16, gridGap: 12 }`, `motion.sheetDuration` 200 (`duration-200` on `Sheet`).
- Output: header line `// Generated by scripts/gen-tokens.mjs from tokens.css. Do not edit; run npm run gen:tokens.`, a blank line, then for each group in the order `colors, radius, spacing, type, motion, shadows`: `export const <group> = <JSON.stringify(value, null, 2)> as const` and a newline, groups separated by a blank line. Quoted keys are fine for ESLint and `tsc`. Deterministic, so the drift test compares strings.

### 2. Drift test: `packages/ui/scripts/gen-tokens.test.ts`
`// @vitest-environment node`. Loads the generator with `await import(pathToFileURL(join(here, 'gen-tokens.mjs')).href)` (a computed specifier, so `tsc` does not need a declaration for the `.mjs`; typed by a local cast `as (css: string) => string`). Reads `src/tokens.css` and `src/tokens.ts` with `readFileSync`. The shape scenarios import `{ colors, radius, spacing, type, motion, shadows }` from `'../src/tokens'` and compare with `toEqual`. The package-exports scenario reads `package.json` with `readFileSync` + `JSON.parse`. Vitest already includes `scripts/**/*.test.ts`.

### 3. Literal-colour exemption
`src/no-literal-colors.test.ts` adds `'tokens.ts'` to the ignore list (the matcher already skips `tokens.css` by basename). The new test in that file proves the exemption is real: `matchLiteralColors(readFileSync(tokens.ts))` is non-empty and `findLiteralColors(src, ignore)` has no entry whose `file` is `tokens.ts`.

### 4. `formatInr` entry
Move the function body unchanged (with its comment) to `src/format.ts`, which has no `import`. `price.tsx` imports it for `Price` and re-exports it with `export { formatInr } from './format'`, so `index.ts` (`export * from './price'`) is untouched and every app import keeps working. `src/format.test.ts` (`// @vitest-environment node`) reads its own module's source to assert no `import`, then calls the function. The "entry still exports" scenario goes in `price.test.tsx` (jsdom, because `index.ts` imports the fontsource CSS): `import { formatInr as fromIndex } from './index'` and `expect(fromIndex).toBe(formatInr)` with `formatInr` from `./format`.

### 5. `package.json`
Two `exports` entries inserted after the `"./testing"` block and before `"./tokens.css"`:
`"./tokens": { "types": "./dist/tokens.d.ts", "default": "./dist/tokens.js" }` and `"./format": { "types": "./dist/format.d.ts", "default": "./dist/format.js" }`.
One script appended after `"test"`: `"gen:tokens": "node scripts/gen-tokens.mjs"`. Placement keeps clear of ui-P3-L2, which edits the `gen:api` line and adds an entry after `"./api"`, so whichever lands second rebases without a conflict. `tsconfig.build.json` already builds every file in `src/`, so `dist/tokens.js` and `dist/format.js` appear with no config change (verified by a throwaway build in this worktree).

## Simplifications and ceilings
- `FIXED` values (pill, spacing, sheet duration) are not read from `tokens.css`; the drift test pins them through the shape scenario only. Ceiling: if Spec 1 ever changes them, edit `FIXED`; move them into `tokens.css` as `@theme` variables when the web side needs them as utilities.
- `spacing` is phone-only (`gutter` 16); the desktop gutter 24 is omitted because the only consumer is phone-width (D38). Add `gutterDesktop` when a non-CSS consumer needs it.
- The shadow parser accepts only `x y blur rgba(r, g, b, a)`; a spread value or another colour form throws. Ceiling: extend the regex when a shadow token changes shape.
- `gen:tokens` is not part of `make gen` (platform's Makefile); the drift test in `make test-web` and CI catches a forgotten regeneration.
- Regex parsing, not a CSS parser, as in `check-figma-tokens.mjs`; a comment containing `--x: y;` inside a block would be read as a token.
- `formatInr` relies on `Intl.NumberFormat('en-IN', { currency: 'INR' })`; Hermes ships `Intl`, but its output on device is not tested here (the mobile lane's device walk covers it).

## Risks / Trade-offs
- Metro or Jest in `apps/mobile` must resolve package `exports` and run after the `packages/ui` build; mobile-P4-L1 owns that wiring.
- A parallel ui lane (ui-P3-L2) edits `package.json`; placement in §5 avoids overlapping hunks.
