D31 copied core's runtime into the rider service; core-hygiene (`openspec/changes/archive/2026-10-15-core-hygiene/`) then changed core, and rider-hygiene (`openspec/changes/archive/2026-10-16-rider-hygiene/`) carried over two of its five decisions. Against core on `main` (49553f4):

- Neither `services/core/openapi.json` nor `services/rider/openapi.json` lists a 405 on any operation; the rider contract test (`internal/app` "Router and contract agree") does not expect one.

The whole design was spiked in this worktree on 49553f4 (tree restored before the commit): `TestStartSessionSweepsExpired` failed (`expired session still stored (1 rows), want swept`) before the sweep and passed after; the Task 2 tests failed to compile (`cfg.TrustProxy undefined`, `limit.TrustProxy undefined`) before the code; with all four diffs below `GOFLAGS=-count=1 make test-rider` was green (all packages ok), `make gen` changed only `services/rider/internal/auth/db/auth.sql.go` (core's sqlc output, `core.d.ts` and `rider.d.ts` unchanged), `make postman` changed nothing. After the change rider `limit.go` is byte-equal to core's and rider `clientIP` is byte-equal to core's.

## Goals / Non-Goals

**Goals:** the rider sweeps expired sessions at sign-in and trusts a proxy only when told, exactly as core does; the rider backlog item closes, with the two items core does not have dropped on the record.

**Non-Goals:** HEAD as GET; 405 per operation in `openapi.json`; an index on `sessions.expires_at` or a periodic sweep; the variable in the Makefile, `deploy/` or the e2e env; core's demo rider (core-hygiene Decision 5, core only); a shared Go module (D31).

## Decisions

### 1. Sweep exactly as core-hygiene Decision 1

New sqlc query `DeleteExpiredSessions :exec` in `queries/auth.sql`, text and comment as core's (naming the rider's `RiderSession` check), generated by `sqlc generate` (`make gen`). `startSession` runs it before `newToken`, with core's `ponytail:` comment. The rider has one session start (sign-in), so one call covers the requirement. The sweep is a separate statement, not a transaction with the insert: a failed sweep fails the sign-in with 500 (as core), a sweep that succeeds and an insert that fails loses nothing live. Ceiling (core's): a sequential scan of `sessions` per sign-in; add the index or a periodic sweep if sign-ins or live sessions grow large. Concurrent sign-ins may race on the same rows; `delete` is idempotent, so the loser deletes zero rows.

### 2. Trusted proxy exactly as core-hygiene Decision 4

`config.Config.TrustProxy` parsed with core's switch (`TrimSpace`; `""`/`false` false; `true` true; anything else one problem `SHOPPERSTOP_RIDER_TRUST_PROXY must be true or false (got %q)` joined with the others). `Limiter.TrustProxy` field and comments as core's; `clientIP(r, trustProxy)` and its call in `refused` as core's; `cmd/rider/main.go` builds the limiter in a variable and sets the field before `auth.New`, as core's `main.go`. The field is set once before serving and only read afterwards, so no lock (core's reasoning). `TRUE` and `1` are refused, as in core. Ceiling (core's): `true` behind anything that does not overwrite `X-Forwarded-For` lets a client choose its key; the variable is off by default and nothing in the repository sets it (Caddy in `deploy/` is not in front of the rider in dev or e2e).

### 3. HEAD answered as GET: dropped (matches core)

core does not answer HEAD as GET: its router answers HEAD on a GET route with 405 `Allow: GET` (spike above), and core-hygiene's proposal lists "HEAD support" as out of scope. The rider already does the same since rider-P4-L1. D31 asks the copies to match core, so the rider keeps 405; serving HEAD would make the rider the only service that does. If HEAD is wanted, it is one `middleware.GetHead` (chi, already a dependency) in both routers, a platform-wide change proposed by core first and copied here. Nothing probes with HEAD today (`deploy/Caddyfile` has no health check; the Playwright configs poll `healthz` with GET).

### 4. 405 per operation in `openapi.json`: dropped

The Spec 1 §11 rule covers every served route and its error codes; a wrong-method 405 comes from the router, not from a route; neither contract lists it and the contract test does not expect it (orchestrator decision, 2026-10-16). `method_not_allowed` is already in the rider's `Error.code` enum (rider-P4-L1), so clients can type it. No `rider.d.ts` or Postman regeneration.

### 5. Tests are core's, renamed where the rider names differ

`TestStartSessionSweepsExpired` (internal/auth) is core's with four riders instead of customer and staff, and it also checks the new session row. `TestLoadTrustProxy` (internal/config) is core's with the rider variable. `TestRiderSignInRateLimitedPerIP`, `TestRiderSignInRateLimitedPerForwardedIP` and `TestRiderSignInEmptyForwardedForFallsBackToConnection` (internal/app) are core's three tests with a `Rider` prefix, the rider's `signInPath`, a `signedUpEmail` helper over `seedRider`, and `New(testPool, nil, a, nil)`. `TestRiderSignInRateLimitedPerIP` pins the untrusted default, which already holds; it lands with the other red tests in the `test:` commit (the package does not compile until Task 2's code).

## Risks / Trade-offs

- [The sweep deletes an expired row another test still reads] → none does: every test that expires a session only asserts that its token answers 401, which a missing row also gives; the spike's full suite is green.
- [Someone sets `SHOPPERSTOP_RIDER_TRUST_PROXY=true` without an overwriting proxy] → a client picks its IP bucket; the per-email limit still holds. Documented on the field, as in core.
- [The sqlc output drifts from `sqlc generate`] → the worker generates it with `make gen` and commits it; the manager re-runs `make gen` and expects a clean tree.
