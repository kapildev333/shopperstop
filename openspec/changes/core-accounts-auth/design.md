# Design

## Context
Builds on `core-service-foundation` (archived 2026-10-12): `httpx` router with request id, log-and-recover and CORS; `ReadJSON` with the 1 MiB and NUL checks; `migrate.Apply` over `migrations.FS`; `testdb.Open` giving a per-package schema; `app.New` registering flat full paths so `chi.Walk` sees them; the contract test. Behaviour comes from this change's deltas (`accounts`, `admin-staff`, `platform`). Constraints: stdlib, chi, pgx v5, `golang.org/x/crypto/bcrypt`, sqlc output; tests on the real `shopperstop_core_test` database, no mocks; the limiter's clock is the only fake (process boundary). PLAN.md D3 (sqlc arrives now), D16 (`internal/pg` arrives now), D19 (regenerate `core.d.ts`), D20 (bearer security, `/admin/` prefix, `token` in auth examples, fixed demo ids), D22 (seed grows per lane).

A spike on 2026-10-12 (scratch copy, sqlc v1.31.1, Postgres 16 container) confirmed the migration, `sqlc.yaml` and both query files below verbatim: they generate, compile, and against the real test database `citext` lookups ignore case, uuid columns scan into `string` and nullable uuid into `*string`, enums become Go string types, a duplicate email gives SQLSTATE `23505` constraint `customers_email_key`, and the staff session join rejects inactive users. Workers copy them; they do not redesign them.

## Goals / Non-Goals
**Goals:** every scenario in the three deltas has a Go test; later core lanes get `pg.Map`, `testdb.Migrated`, the paging, patch and path-id helpers, `RequireCustomer` / `RequireStaff` / `RequireAdmin`, `auth.CustomerID`, `auth.CurrentStaff` and a seed they extend.

**Non-Goals:** stores and the `staff_users.store_id` foreign key (core-P2-L2), staff dashboard (L5), address `lat`/`lng`, role or store changes on a staff user, session revocation on password reset, `FILES_DIR`, Postman environment changes.

## Schema: `migrations/0002_accounts.sql` (verbatim)
```sql
-- Accounts: customers, staff users, bearer sessions, customer addresses.
create extension if not exists citext with schema public;

create type order_status as enum ('placed', 'accepted', 'packing', 'ready', 'out_for_delivery', 'delivered', 'cancelled');
create type staff_role as enum ('admin', 'store_staff');

create function set_updated_at() returns trigger language plpgsql as $$
begin
    new.updated_at = now();
    return new;
end
$$;

create table customers (
    id            uuid primary key default gen_random_uuid(),
    email         citext not null unique,
    password_hash text not null,
    name          text not null,
    phone         text not null default '',
    created_at    timestamptz not null default now(),
    updated_at    timestamptz not null default now()
);
create trigger customers_updated_at before update on customers for each row execute function set_updated_at();

create table staff_users (
    id            uuid primary key default gen_random_uuid(),
    email         citext not null unique,
    password_hash text not null,
    name          text not null,
    role          staff_role not null,
    store_id      uuid,
    is_active     boolean not null default true,
    created_at    timestamptz not null default now(),
    updated_at    timestamptz not null default now(),
    constraint staff_users_admin_has_no_store check ((role = 'admin') = (store_id is null))
);
create trigger staff_users_updated_at before update on staff_users for each row execute function set_updated_at();

create table sessions (
    id           uuid primary key default gen_random_uuid(),
    token_hash   bytea not null unique,
    subject_type text not null check (subject_type in ('customer', 'staff')),
    subject_id   uuid not null,
    expires_at   timestamptz not null,
    last_seen_at timestamptz not null default now(),
    created_at   timestamptz not null default now(),
    updated_at   timestamptz not null default now()
);
create trigger sessions_updated_at before update on sessions for each row execute function set_updated_at();

create table addresses (
    id          uuid primary key default gen_random_uuid(),
    customer_id uuid not null references customers (id) on delete cascade,
    label       text not null,
    line1       text not null,
    line2       text not null default '',
    pincode     text not null,
    is_default  boolean not null default false,
    created_at  timestamptz not null default now(),
    updated_at  timestamptz not null default now()
);
create index addresses_customer_id on addresses (customer_id);
create unique index addresses_one_default on addresses (customer_id) where is_default;
create trigger addresses_updated_at before update on addresses for each row execute function set_updated_at();
```

### `queries/auth.sql` (verbatim)
```sql
-- name: CreateCustomer :one
insert into customers (email, password_hash, name)
values ($1, $2, $3)
returning id, email, name, phone;

-- name: CustomerByEmail :one
select id, email, password_hash, name, phone from customers where email = $1;

-- name: CustomerByID :one
select id, email, name, phone from customers where id = $1;

-- name: UpdateCustomer :one
update customers
set name = coalesce(sqlc.narg(name), name), phone = coalesce(sqlc.narg(phone), phone)
where id = @id
returning id, email, name, phone;

-- name: CreateCustomerSession :exec
insert into sessions (token_hash, subject_type, subject_id, expires_at)
values ($1, 'customer', $2, now() + interval '30 days');

-- name: CreateStaffSession :exec
insert into sessions (token_hash, subject_type, subject_id, expires_at)
values ($1, 'staff', $2, now() + interval '12 hours');

-- name: CustomerSession :one
select id, subject_id from sessions
where token_hash = $1 and subject_type = 'customer' and expires_at > now();

-- name: TouchCustomerSession :exec
update sessions set last_seen_at = now(), expires_at = now() + interval '30 days'
where id = $1 and last_seen_at < now() - interval '1 hour';

-- name: StaffSession :one
select s.id as session_id, u.id, u.email, u.name, u.role, u.store_id, u.is_active
from sessions s join staff_users u on u.id = s.subject_id
where s.token_hash = $1 and s.subject_type = 'staff' and s.expires_at > now() and u.is_active;

-- name: DeleteSession :exec
delete from sessions where id = $1;

-- name: CreateStaff :one
insert into staff_users (email, password_hash, name, role, store_id)
values ($1, $2, $3, $4, $5)
returning id, email, name, role, store_id, is_active;

-- name: StaffByEmail :one
select id, email, password_hash, name, role, store_id, is_active from staff_users where email = $1;

-- name: ListStaff :many
select id, email, name, role, store_id, is_active from staff_users
order by email limit $1 offset $2;

-- name: CountStaff :one
select count(*) from staff_users;

-- name: UpdateStaff :one
update staff_users
set name = coalesce(sqlc.narg(name), name),
    password_hash = coalesce(sqlc.narg(password_hash), password_hash),
    is_active = coalesce(sqlc.narg(is_active), is_active)
where id = @id
returning id, email, name, role, store_id, is_active;
```

### `queries/address.sql` (verbatim)
```sql
-- name: ListAddresses :many
select id, label, line1, line2, pincode, is_default from addresses
where customer_id = $1
order by is_default desc, created_at desc, id
limit $2 offset $3;

-- name: CountAddresses :one
select count(*) from addresses where customer_id = $1;

-- name: CreateAddress :one
insert into addresses (customer_id, label, line1, line2, pincode, is_default)
values ($1, $2, $3, $4, $5, $6)
returning id, label, line1, line2, pincode, is_default;

-- name: ClearDefaultAddress :exec
update addresses set is_default = false where customer_id = $1 and is_default;

-- name: UpdateAddress :one
update addresses
set label = coalesce(sqlc.narg(label), label),
    line1 = coalesce(sqlc.narg(line1), line1),
    line2 = coalesce(sqlc.narg(line2), line2),
    pincode = coalesce(sqlc.narg(pincode), pincode),
    is_default = coalesce(sqlc.narg(is_default), is_default)
where id = @id and customer_id = @customer_id
returning id, label, line1, line2, pincode, is_default;

-- name: DeleteAddress :execrows
delete from addresses where id = $1 and customer_id = $2;
```

## Decisions
1. **Ownership.** `internal/auth` owns `customers`, `staff_users` and `sessions` (sign-in reads staff users, so staff-user management lives with it; Spec 2 §9 puts staff users in `internal/staff`, which arrives with the dashboard in core-P2-L5 and calls `auth` for nothing it does not need). `internal/address` owns `addresses`. `internal/seed` is the one package allowed to write other packages' tables (Spec 2 §9 lists it as the demo loader). Ceiling: none until a second writer of `staff_users` appears.
2. **`citext` lives in `public`.** `create extension if not exists citext with schema public`: the extension is per database, the test schemas are per package, so the type must sit in a schema every search path holds. `testdb.Open` sets `search_path` to `"<schema>", public` (tables still go to the first schema). Without `public` in the path the `citext` type and its `=` operator are not found (spike). The `shopperstop_core` role owns its databases, so it may create this trusted extension (spike).
3. **`testdb.Migrated` serialises migration with an advisory lock.** Two packages migrating at once race on `create extension` (unique violation on `pg_extension`). `Migrated` acquires one pooled connection, runs `select pg_advisory_lock(727001)`, calls `migrate.Apply(ctx, pool, migrations.FS)`, then `pg_advisory_unlock`, releases, and panics on any error (as `Open` does). `migrate`'s own tests keep using `Open`. Ceiling: tests migrate one package at a time (about 50 ms each).
4. **No pool helper and no `pg.WithTx`.** `pgxpool.New` is the pool helper and `pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error { q := db.New(tx); ... })` is the transaction (commit on nil, rollback on error or panic). `internal/pg` holds only `Map` and `IsUnique`. Ceiling: none; add `WithTx` when a transaction needs retry on serialization failure.
5. **Times come from the database clock.** Session expiry and last use are computed in SQL with `now()`; tests move time by updating rows (`update sessions set last_seen_at = now() - interval '2 hours' where ...`). The only Go clock is the limiter's `now func() time.Time`, faked in its unit test. Ceiling: none.
6. **Tokens.** 32 bytes from `crypto/rand`, `base64.RawURLEncoding` (43 characters). Stored `token_hash = sha256([]byte(token) + pepper)` over the token text as sent. `Authorization` must be `Bearer <token>` with the scheme compared without case and a non-empty token; anything else is 401 "sign in required" (no database call).
7. **Customer sessions slide in SQL.** `RequireCustomer`: `CustomerSession(hash)` (no rows → 401), then `TouchCustomerSession(id)`, whose `where last_seen_at < now() - interval '1 hour'` makes it a no-op within the hour; then the context gets the customer id and session id and `httpx.SetSubject(ctx, "customer", id)`. Ceiling: one extra `update` statement per customer request (usually zero rows); skip it in Go if it shows up in profiles.
8. **Staff sessions are fixed.** `CreateStaffSession` sets `expires_at = now() + 12 hours`; `RequireStaff` runs `StaffSession(hash)`, whose join requires `u.is_active`, and never touches the row. Deactivation therefore ends sessions at once without deleting them. `RequireAdmin` is `RequireStaff` plus `role = 'admin'`, else 403 `forbidden`.
9. **Expired sessions are never swept.** Lookups filter `expires_at > now()`. Ceiling: rows grow with sign-ins; add a `delete ... where expires_at < now()` to `core-admin` when the table passes a million rows.
10. **Sign-in does equal work for unknown emails.** On no rows the handler still runs `bcrypt.CompareHashAndPassword` against a dummy hash made once (`sync.OnceValue`) so timing does not reveal registered emails. The 401 message is the same for every failure.
11. **Limiter: fixed windows per key, counted before validation.** Register, sign-in and staff sign-in decode the body (`ReadJSON`; malformed is 400 and not counted), then call `Allow(email, ip)`: keys `email:<lower(trim(email))>` and `ip:<host of r.RemoteAddr>`; each key's window starts at its first attempt and lasts `window`; every call counts against both keys; it returns false when either count exceeds its limit. Production: `NewLimiter(10, 100, time.Hour, time.Now)` in `cmd/core`. When the map holds more than 10 000 keys, `Allow` first drops keys whose window ended. One limiter is shared by the three routes. Ceilings: per process (Spec 2 §5); behind a proxy every client shares the proxy's IP bucket of 100, so trust `X-Forwarded-For` from a configured proxy when core runs behind Caddy for real users.
12. **Validation, first failing field wins.** Email: trimmed, at most 254 bytes, `mail.ParseAddress(e)` succeeds and its `Address == e`. Password: 8 to 72 bytes, not trimmed. Name: trimmed, 1 to 100 runes, stored trimmed. Phone: `""` or `^\+?[0-9]{10,15}$`. Label 1 to 40 runes trimmed, line1 1 to 200 trimmed, line2 0 to 200 trimmed, pincode `^[1-9][0-9]{5}$`. Role `admin` or `store_staff`; `storeId` a canonical uuid, required for `store_staff`, refused for `admin` (field `storeId` either way). Each failure is 400 `validation` with the JSON field name in `field` (web request 4). Validation runs in Go so the 400 comes before any write; the database checks stay as a backstop.
13. **PATCH semantics.** `httpx.ReadPatch` decodes with `ReadJSON` into `json.RawMessage`, requires a JSON object (else 400 "invalid JSON"), refuses any member whose value is `null` (400 `validation`, field = that member, message "must not be null"; members checked in sorted order), then unmarshals into `dst`, whose fields are pointers. Absent member: unchanged (`coalesce(sqlc.narg(x), x)`); `""` for `phone` or `line2` clears it, and cleared fields are omitted from responses (web request 2). An empty object `{}` returns the row unchanged.
14. **Paging.** `httpx.Page` reads `page` and `pageSize` with `strconv.Atoi`; absent means 1 and 24; `page < 1`, `pageSize` outside 1..100 or non-integer is 400 `validation` naming the parameter. Queries take `limit = pageSize`, `offset = (page-1)*pageSize`; `total` is a separate `count(*)`. Ceiling: offset paging; switch to keyset when a list passes 10 000 rows (orders, later).
15. **Path ids.** `httpx.PathID` accepts only the canonical 36-character form (hex with hyphens at 8, 13, 18, 23; either case); anything else is 404 `not_found`, so a malformed id never reaches Postgres as a cast error.
16. **Subject in the request log.** `logAndRecover` stores a `*subject{typ, id}` in the request context before calling `next`; `httpx.SetSubject` fills it; the log line adds `subjectType` and `subjectId` only when `typ != ""`. The auth middlewares call `SetSubject`.
17. **Addresses and the single default.** `Create` and `Update` with `isDefault` true run in `pgx.BeginFunc`: `ClearDefaultAddress(customerID)` then the insert or update, so the partial unique index never sees two defaults. `Update` with no rows → `pg.Map` → 404. `Delete` uses `:execrows`; 0 rows → 404. Lists order default first, then newest. A new address is not made default automatically (the client sends `isDefault`). No cap on addresses per customer. `GET /me/addresses` answers the standard list shape (web request 5).
18. **Register returns a session** `{token, customer}` with 201, exactly like sign-in's 200 body (web request 1, Spec 2 §5 does not forbid it). Register: decode → `Allow` → validate → `HashPassword` → `CreateCustomer` (`pg.IsUnique` → 409 field `email`) → new session → 201. Customer creation and session creation are two statements without a transaction; a failure between them leaves an account the customer can sign in to. Ceiling: none worth a transaction.
19. **Staff users.** `CreateStaff` validates (Decision 12), hashes, inserts (`IsUnique` → 409 field `email`) and is shared by `POST /admin/staff-users`, `create-admin` and tests. `UpdateStaffUser` takes `{name?, password?, isActive?}` via `ReadPatch`, validates present fields, hashes a new password, runs `UpdateStaff` (no rows → 404). An admin may deactivate themselves; recovery is `core-admin create-admin` with another email. `storeId` is not checked against `stores` until core-P2-L2 adds the foreign key (request in the lane log). Ceiling: role and store cannot be changed; create a new staff user instead.
20. **`core-admin create-admin <email>`** loads the full config (like `migrate`), opens the pool, and calls `createAdmin`, which reads the first line of `stdin` (strip a trailing `\n` and `\r`; empty input is "password is required"), calls `auth.CreateStaff` with name `Admin` and role `admin`, prints `created admin <email>`. Any error goes to stderr, exit 1. Usage line: `usage: core-admin migrate | seed-demo [--reset] | create-admin <email>`. The password is read from stdin so it never appears in shell history or `ps`; a terminal echoes it (no `x/term`, it is not in the stack). Example: `printf '%s\n' 'rootpass123' | go run ./cmd/core-admin create-admin root@example.com`.
21. **Seed (D22).** `seed.Reset` runs in one transaction: `truncate sessions, addresses, customers, staff_users` then `Load`'s inserts; `Load` alone inserts (a rerun without `--reset` fails on the primary key and `seed-demo` exits 1 naming it). Rows are inserted with explicit ids by plain `tx.Exec` (no sqlc: fixed data, one caller). Hashes come from `auth.HashPassword` (two bcrypt calls, under a second). `core-admin seed-demo [--reset]` loads the full config, opens the pool, runs `Reset` or `Load`, prints `seed-demo: demo accounts loaded`. Later lanes add their tables to the truncate list and their rows to `Load`. Ceiling: no guard against a non-local database; it is a dev command run by `make dev`, `make seed` and `make e2e`.
22. **Fixed demo ids (D20, D22)**, a documented block per kind so later lanes extend it without clashes:

| Row | Id | Values |
|---|---|---|

## Test strategy
Tests run under `make test-core` (`go test -race ./...` from `services/core` on `shopperstop_core_test`). Packages and their schema: `pg` → `Migrated("pg")`, `auth` → `Migrated("auth")`, `app` → `Migrated("app")` (its `TestMain` switches from `Open`), `seed` → `Migrated("seed")`, `cmd/core-admin` → `Migrated("coreadmin")`, `httpx` and `config` need no database, `migrate` keeps `Open`. bcrypt cost 12 takes about 250 ms per hash or compare (more under `-race`): route tests register one customer and create one admin and one store-staff user per package through a `sync.Once` fixture and reuse their tokens; tests that need their own account use unique emails (`<test name>@example.com` lower-cased) and may call `t.Parallel()` unless they capture the default logger. Route tests check status, the envelope `code` and `field`, and the body shape through the real router (`srv`); the auth-gate matrix (`TestAuthGates`) sends every authenticated route anonymously, with a customer token, with a store-staff token and with an admin token and checks 401 / 401 / 403 or 2xx-or-validation / allowed as the Routes table says. Database state for scenarios about storage (hash, sliding expiry) is read and backdated with `testPool.Exec` / `QueryRow` in the test.

## Risks / Trade-offs
- [`scripts/postman.test.mjs` asserts the real contract has exactly one folder `platform` with two requests] → `make postman` fails as soon as task 5 adds routes. Request to platform: assert the `platform` folder's contents, not the folder count (or use a Phase 1 fixture). Until it lands, task 10 reports the failure instead of editing `scripts/`.
- [`make postman` rewrites `docs/postman/shopperstop-core.postman_collection.json`, a platform file] → the gate "`make gen postman` leaves `git status` clean" needs the regenerated collection committed in this PR. Escalated: extend D19's mechanical exception to the collection, or platform regenerates it right after merge.
- [CI installs `sqlc@latest`] → generated headers change with the version. Request to platform: pin `v1.31.1`.
- [`go get golang.org/x/crypto` needs network in the worker sandbox] → task 4 reports instead of vendoring.
- [`staff_users.store_id` has no foreign key yet] → any uuid is accepted for store staff until core-P2-L2 adds `stores` and the constraint; L2 must map the violation on create to 400 `validation` field `storeId` (pg.Map would say 409).
- [bcrypt makes the suite slower] → shared fixtures (Test strategy); the limiter route test uses cheap invalid bodies after the limiter so most attempts never hash.
